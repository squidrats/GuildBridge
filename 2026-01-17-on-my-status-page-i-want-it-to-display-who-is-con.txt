● Deep Investigation Summary

  Root Cause Analysis

  The D/Cs in large raids during zone transitions were likely caused by:

  1. Handshake PONG responses during zone transitions - When receiving a HELLO handshake, the addon immediately sent a PONG response, even during zone transitions. In a large raid with many guildmates/BNet friends, multiple handshakes could arrive simultaneously.
  2. BNet API calls (lookupCharacterName) during zone transitions - Every incoming handshake triggered BNet API calls to look up character names, iterating through all BNet friends.
  3. Queue processing continuing during zone transitions - Even though new messages were blocked, the queues continued processing messages that were already queued.
  4. Roster requests being handled during zone transitions - When someone requested your roster, you'd send the full roster (multiple chunks) even during zone transitions.

  All Fixes Applied

  Core.lua:
  - ProcessQueue: Now pauses during zone transitions and resumes after 8 seconds

  Messages.lua:
  - ProcessGuildRelayQueue: Now pauses during zone transitions
  - SendBridgePayload: Zone transition check (already added earlier)
  - SendWhisperBridgePayload: Zone transition check (already added earlier)
  - RelayToOtherGuilds: Zone transition check (already added earlier)
  - RelayToGuildmates: Zone transition check (already added earlier)
  - HandleGuildChatMessage: Zone transition check before relaying

  Handshake.lua:
  - lookupCharacterName: Now skips BNet API calls during zone transitions
  - HandleHandshakeMessage: Wrapped PONG response, relay announcements, and roster requests in zone transition check
  - HandleWhisperHandshakeMessage: Same protection for whisper handshakes

  RosterSync.lua:
  - ProcessRosterRequestQueue: Now pauses during zone transitions
  - HandleRosterRequest: Now skips sending full roster during zone transitions

  Events.lua:
  - Added ZONE_CHANGED_NEW_AREA event handler (already added earlier)

  The Large Raid Factor

  In a large raid:
  - More BNet friends nearby = more handshakes
  - More guildmates = more roster activity
  - GROUP_ROSTER_UPDATE fires more frequently
  - Zone transitions cause more state changes for 40 players

  All these factors combined could trigger message bursts that caused D/Cs. The comprehensive zone transition protection should now prevent all outgoing messages and expensive API calls during the 8-second cooldown period.

  What Gets Logged

  - SEND - Every message sent (BNet, Whisper, Guild) with type and size
  - RECV - Every message received with type, sender, and size
  - EVENT - Key events (ZONE_CHANGED_NEW_AREA, GROUP_ROSTER_UPDATE, GUILD_ROSTER_UPDATE, BN_FRIEND_INFO_CHANGED, CHAT_MSG_GUILD)
  - QUEUE - When queues pause due to zone transitions
  - GQUEUE - Guild relay queue pauses

  Log Format

  Each entry shows:
  [HH:MM:SS|GameTime] CATEGORY ZT Q:X GQ:Y | message
  - ZT appears if in zone transition
  - Q:X = main queue size
  - GQ:Y = guild relay queue size

  How to Use

  1. On both characters, run: /mndclog on
  2. Play normally until you D/C
  3. After logging back in, run: /mndclog copy
  4. Select all (Ctrl+A), copy (Ctrl+C), and paste it here

  The log persists in SavedVariables, so it survives the disconnect. We'll be able to see exactly what was happening right before the D/C - what messages were being sent/received, what events fired, queue sizes, etc.
